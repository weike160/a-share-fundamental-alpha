# 每日模拟实盘

使用现有完整特征 LightGBM 配方：真实行情、财报与模型预测驱动虚拟账户，不连接券商、不发送真实委托。

## 运行

在项目目录安装 `pip install -e '.[paper]'`；运行完整测试还需安装 `.[dev]`。本机已经配置 `.venv/bin/python`。

试用先执行 `.venv/bin/python scripts/run_paper.py check` 查看启动缺项。未接入模型也可以启动真实行情下的空仓账户和日报；日报会标记“已结算、未选股”，不会把空仓收益当成模型测试。已有订单不会因模型或财报接口故障停止结算。

```sh
# 先恢复研究时的分析面板，再导出固定版本模型（日期须早于当天）
.venv/bin/python scripts/run_paper.py train --panel data/processed/analysis_panel.parquet --cutoff 2026-09-13

# 北京时间 16:00 后运行，默认账户 100 万元
.venv/bin/python scripts/run_paper.py daily

# 完全离线的 30 个交易日演示，与正式资金账本隔离
.venv/bin/python scripts/run_paper.py demo

# 离线检查模型与账户
.venv/bin/python scripts/run_paper.py check

# 补记漏跑日期：只重放已保存快照，或恢复完全空仓的日期
.venv/bin/python scripts/run_paper.py recover --through 2026-09-14

.venv/bin/python -m pytest tests/test_paper.py tests/test_paper_model.py tests/test_paper_feed.py tests/test_paper_recovery.py -q
```

`train` 使用已有项目的 10 个特征和 LightGBM 参数重新拟合并导出，不声称恢复原来某一折的模型。只有 `exit_date_adj_20d` 已到达截止日的标签可以训练。预处理参数、特征顺序、训练截止日、源文件校验和随模型保存。模型文件为原生文本，元数据为 JSON。

Git 仓库不提交 `analysis_panel.parquet`、账户账本或已训练模型；新环境需要从研究数据快照恢复训练面板并显式执行 `train`。没有模型时系统生成诊断日报，不使用随机分数替代模型。训练输出默认 `paper_models/current/{model.txt,metadata.json}`，禁止覆盖已有版本；活跃账户冻结模型版本及参数。替换模型须开新账户做对照。

## 日报与账本

- `paper_output/live/latest.md`：最新日报或具体阻塞原因。
- `paper_output/live/reports/YYYY-MM-DD.md`：成功结算后的历史日报。
- `paper_output/live/equity.csv`：资产、盈亏、收益、指数参照与回撤。
- `paper_output/live/trades.csv`、`orders.csv`：成交及未成交原因。
- `paper_output/live/candidates.csv`：最新日结的候选分数与特征；完整历史保存在每日快照中。
- `paper_output/live/account.sqlite3`：权威账户账本，事务保存整个日结。
- `paper_output/live/snapshots/YYYY-MM-DD.json`：不可变的当日数据、分数、模型信息。
- `paper_output/live/status.json`：自动任务读取的状态。失败退出码为 2。
- `paper_output/demo/`：仅合成数据演示，绝不并入正式收益。

日报可从账本重复生成。进程锁避免并发运行，数据库日期唯一约束避免重复成交；同日快照内容改变时拒绝覆盖。每日运行先尝试恢复断档：有快照则逐日重放；没有快照、且既无持仓也无待执行订单时，按真实历史指数补记现金账户。涉及持仓或待执行订单却无快照时停止，不能用后来的财报补造当时的信号。同日已结算后恢复模型，选股从下一交易日开始。

## 策略与交易假设

每天获取最近两个报告期中 35 个自然日内的公告，再仅考虑上次成功结算日以来披露的新事件；首日从上一个交易日开始，包含周末与上次采集后晚间披露的公告，已考虑过的事件不会反复筛选。启动时不追买上一轮财报季的陈旧事件。按当日新事件模型分数取前 20%，最多 20 只，单只新订单预算不超过前日结算资产 5%。持仓随市场上涨可能超过该比例，本版不强制再平衡。仓位不足时持有现金，不强行凑满；非财报披露季可能长时间没有新买单。

每只股票只开一个持仓，持有满 20 个交易日后于当日收盘发卖单，下一交易日撮合；未成交卖单会继续尝试。买单未成交或部分成交的余量当日取消，不自动追买。卖出优先于买入，但不会提前使用尚未实现的卖出所得增加昨晚的买入预算。

第一版范围为沪深主板普通股票，排除 ST、退市标记、新股标记，以及 160 个自然日内行情不足 60 条的证券。暂未接入创业板、科创板、北交所等差异化交易规则。此范围与原研究全市场样本不同，不能直接对比历史年化数字。

收盘后采集完成当日数据，处理**前一个交易日已经生成**的订单，以当日未复权开盘价加减 10bp 滑点模拟成交，并限制在当日高低价和涨跌停范围内。开盘触及对应涨跌停边界则不成交，成交量上限为全日成交股数的 1%。这属于收盘后确认的日线撮合近似，不能证明开盘时有这么多可成交量。100 股买入单位、T+1、现金余额、最低佣金都进入账户计算。

默认费用是假设参数：双边佣金 3bp、每单最低 5 元、卖出印花税 5bp、双边过户费 0.1bp；实测前应与目标券商核对。参数集中在 `paper/engine.py` 的 `Settings`，新账户可由 Python 调用传入配置，已有账户不得无记录变更。

行情缺失不伪装成停牌。所有持仓及待执行订单必须有当日可靠行情；新候选数据不完整、模型或财报故障时，暂停全部新选股并单独结算已有账户，避免因抓取失败改变排序。异常除权参考价会暂停并要求核对；第一版没有自动处理分红、送转、配股或退市结算。正常停牌若数据源提供有效当日标记和价格则保持持仓，否则暂停。

选股失败期间保留上次成功筛选的日期，恢复后在 35 天窗口内重新考虑遗漏的新事件；所有新订单仍只能从恢复后的下一交易日成交。数据源迟于成功筛选日才补录的旧公告仍可能遗漏。日结成功但未能选股时，`status.json` 返回 `settled_without_selection`，日报清楚列出原因。空候选日会清空候选导出表，防止误读昨日选股。

## 模型与数据限制

在线特征不依赖未来收益标签。增长类特征按精确去年同期匹配；行情特征截至当前收盘；财报可用时点以实际披露日期和本次首次观察时间共同约束，最早次日成交。SUE 历史可能含后续修订；上线时保存快照保证之后可追溯，但不能消除原训练面板已有的历史修订偏差。

原研究 `sue_neutral` 使用整个报告期的截面。在线只有当前可得的新事件，因此采用当前事件截面计算，可能与原模型训练分布不同；样本少于 20 条时该特征缺失，用训练中位数填充。每行至少半数特征有效才允许评分。这个差异随模型记录在元数据中，后续应使用累积的前向快照重建一致的训练集进行对照。

沪深300价格指数自首个成功结算日收盘起归一化，作为大盘参照，未加交易成本，不是同风险可交易基准；日报收益差不能直接称为 Alpha。模拟测试用于验证系统和前向表现，历史研究结果不会填入本账户。

数据字段参照 [AKShare 股票接口](https://akshare.akfamily.xyz/data/stock/stock.html)，撮合局限参照 [QuantConnect 模拟交易说明](https://www.quantconnect.com/docs/v2/cloud-platform/live-trading/brokerages/quantconnect-paper-trading)。

指数、证券状态和个股日线优先东财，接口故障时回退新浪；东财成交量以手计，新浪以股计，适配器统一为股。数据采集超过 15 分钟会退出并记录诊断，不提交不完整日结。财报仍依赖东财、EPS 历史依赖同花顺，可用性需要持续观察。

已在当前任务配置工作日北京时间 18:00 的自动运行；成功日结后汇报收益，休市、重复运行或已知阻塞未变化时保持安静。本地任务需要电脑开机、应用运行且网络可用，参照 [官方定时任务说明](https://learn.chatgpt.com/docs/automations?surface=app)。
