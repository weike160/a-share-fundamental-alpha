# v1.0：AKShare 最小研究闭环

状态：开发中

## 目标

基于 AKShare 公开接口完成一条可运行的 A 股财报事件研究链路：下载并缓存数据，按实际披露日期确定信号可用时间，构造季节性随机游走 SUE，完成因子检验、简化组合回测和交易成本拆解。

本阶段只解释公开数据能够支持的结论。财务历史版本、完整历史股票池、历史 ST 状态和公告精确时刻无法恢复时，结果中必须保留对应限制。

## 研究范围

| 项目 | 第一版设置 |
|---|---|
| 数据源 | AKShare 公开接口 |
| 股票范围 | 能够匹配财务、披露日期和行情的沪深 A 股事件样本 |
| 样本区间 | 由数据完整性检查后确定并写入配置 |
| 主要信号 | 季节性随机游走 SUE |
| 对照信号 | 净利润同比、营收同比 |
| 收益窗口 | 5、10、20、40 个交易日 |
| 入场规则 | 实际披露日后的首个可交易日 |
| 因子检验 | RankIC、ICIR、五分组收益、IC Decay、横截面回归 |
| 组合 | 高分位 long-only，等权或信号加权 |
| 成本 | 佣金、卖出印花税、固定滑点、ADV 参与率限制 |
| 模型比较 | Ridge 与 LightGBM；基础链路通过后再运行 |

## 数据接口

第一版计划使用以下 AKShare 接口：

| 接口 | 用途 | 主要限制 |
|---|---|---|
| `stock_yjbb_em` | EPS、收入、净利润、ROE、毛利率和行业 | 当前返回的历史值可能包含后续修订 |
| `stock_yysj_em` | 预约日期和实际披露日期 | 通常只有日期，没有盘中时间 |
| `stock_zh_a_hist` | 日频行情、成交量和成交额 | 上游接口可能调整；复权口径需要单独核对 |
| `stock_tfp_em` | 停复牌记录 | 历史覆盖范围需要实测 |

每次下载都保存原始响应，不在研究运行时重复抓取。缓存需要记录 AKShare 版本、下载时间、接口参数、行数和字段名。

## 时间与样本规则

1. `report_period` 表示财务数据所属期间，不能用于决定信号何时可用。
2. `actual_disclosure_date` 来自实际披露日期。
3. 第一版统一在披露日后的下一交易日尝试入场。
4. 下一交易日停牌或无法买入时，顺延至首个可交易日；顺延规则写入结果。
5. 信号标准化、中性化和模型预处理只使用当时已经进入样本的数据。
6. 无法恢复历史版本的财务值需要标记，报告中不得将其描述为完整 Point-in-Time 数据。
7. 无法恢复完整历史股票池时，结果只代表成功匹配的事件样本。

## 信号定义

季节性未预期盈利：

```text
UE(i,t) = EPS(i,t) - EPS(i,t-4)
```

标准化信号：

```text
SUE(i,t) = UE(i,t) / std(UE(i,t-k:t-1))
```

配置中必须明确历史窗口 `k`、最少有效季度数、标准差为零的处理和 EPS 口径。该信号在文档中称为“季节性随机游走 SUE”或“SUE proxy”，不称为分析师一致预期 SUE。

## 输出文件

完成后应由同一条运行命令生成：

```text
results/
├── data_audit.csv
├── sample_events.csv
├── factor_metrics.json
├── ic_by_period.csv
├── quantile_returns.csv
├── robustness.csv
├── model_comparison.csv
└── figures/
    ├── signal_distribution.png
    ├── ic_decay.png
    ├── quantile_returns.png
    └── gross_to_net.png
```

`sample_events.csv` 保存人工审计样本，至少包含报告期、实际披露日期、信号可用日期、首次交易日期和收益计算区间。受授权限制的原始数据不提交到仓库。

## 实现顺序

### 1. 数据闭环

- [ ] 固定 AKShare 版本和研究配置
- [ ] 下载并缓存原始响应
- [ ] 合并财务、披露日期和行情
- [ ] 生成交易日历与首次可交易日期
- [ ] 输出缺失率、覆盖率和匹配失败原因
- [ ] 人工核对至少 20 条事件

### 2. 因子闭环

- [ ] 实现季节性随机游走 SUE
- [ ] 实现净利润和营收同比信号
- [ ] 按事件日去极值、标准化并中性化
- [ ] 计算 5、10、20、40 日 RankIC 和 ICIR
- [ ] 输出五分组收益与 IC Decay
- [ ] 完成行业和市值控制后的横截面回归

### 3. 交易闭环

- [ ] 构建高分位 long-only 组合
- [ ] 处理停牌、涨跌停和顺延成交
- [ ] 加入佣金、卖出印花税和滑点
- [ ] 限制订单占 ADV 的比例
- [ ] 输出 Gross 到 Net 的逐项拆解

### 4. 稳健性与模型比较

- [ ] 按年份、市值和流动性拆分结果
- [ ] 比较公告后第 1 个与第 2 个可交易日入场
- [ ] 运行双倍成本情景
- [ ] 使用 walk-forward 和 purge gap 比较 Ridge 与 LightGBM
- [ ] 使用相同样本和成本口径比较模型

### 5. 交付

- [ ] 一条命令重新生成表格和图
- [ ] 自动化测试覆盖信号、时间对齐、IC、分组和成本
- [ ] README 写入真实样本范围和主要结果
- [ ] 报告同时记录有效、无效和异常实验
- [ ] 简历只引用已经生成并能够复现的数字

## 当日取舍规则

数据审计优先于模型比较。如果事件面板没有通过人工抽查，当日取消 LightGBM，集中修正公告日期、财务口径和收益区间。基础链路通过后仍有时间，再加入 Ridge 与 LightGBM。

复杂组合优化、MLP、SHAP、PDP 和精细市场冲击校准不属于本阶段。它们在公开数据基线稳定后再进入下一阶段。

## 完成标准

满足以下条件后，才能把本阶段写成已完成项目成果：

- 数据下载、清洗、信号、检验和回测可以从配置重新运行。
- 随机抽查的事件没有使用披露日前的信息。
- 结果包含样本量、覆盖率、RankIC、分组收益和成本拆解。
- 失败实验和数据限制随结果一起保留。
- README、报告、代码与简历使用相同的指标口径。

信号显著或组合盈利不属于完成条件。研究结论可以是得到支持、证据不足或被当前实验否定。
